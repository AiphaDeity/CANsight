# CanSight

CanSight 是基于 STM32F407 和 LVGL 的经典 CAN 总线查看与日志记录项目。设备使用触摸屏显示报文，将接收记录保存到 SD 卡，并计划支持在设备上读取历史日志进行回放。

项目保留“接收”和“SD 回放”两个页面，不提供手动发送报文和追踪页面。Windows 模拟器用于开发界面，与 STM32 固件共用界面和字体源码。

## 当前进度

项目处于界面与业务数据接入阶段。真实 CAN 报文显示、日志归档、历史列表刷新及文件切换已完成实机验证。V0.4 新增存储容量显示和历史文件删除，待实机验证；10 MiB 自动切分仍需单独验证，逐帧导航和按时间播放尚未实现。

## 构建 STM32 固件

安装 CMake、Ninja 和 Arm GNU Toolchain，并确保 `cmake`、`ninja`、`arm-none-eabi-gcc`、`arm-none-eabi-g++` 可从终端调用。也可以使用 STM32 开发工具提供的相应工具链环境。

在仓库根目录执行：

```powershell
cmake --preset Debug
cmake --build --preset Debug --parallel 4
```

主要输出：

- `build/Debug/cansight.elf`：烧录和调试文件。
- `build/Debug/cansight.map`：链接映射，用于查看代码和数据占用。

使用 ST-Link 配合 STM32CubeProgrammer 或开发环境，将 ELF 文件烧录到开发板。

Release 构建：

```powershell
cmake --preset Release
cmake --build --preset Release --parallel 4
```

Release 文件位于 `build/Release/`。当前 Debug 使用 `-O0 -g3`，Release 使用 `-Os -g0`。

## 构建 Windows 模拟器

模拟器使用 Windows 本机编译器，不能使用 `arm-none-eabi` 工具链。下面以安装在 `C:/msys64` 的 MSYS2 UCRT64 GCC 为例，要求 CMake 和 Ninja 已加入 `PATH`。

在仓库根目录的 PowerShell 中执行首次配置：

```powershell
cmake -S simulator -B simulator/build -G Ninja `
  -DCMAKE_C_COMPILER=C:/msys64/ucrt64/bin/gcc.exe `
  -DCMAKE_CXX_COMPILER=C:/msys64/ucrt64/bin/g++.exe
```

编译并启动：

```powershell
cmake --build simulator/build --target cansight_sim --parallel 4
.\simulator\build\cansight_sim.exe
```

如果 MSYS2 安装在其他位置，修改编译器路径。若运行时提示缺少 MSYS2 运行库，将对应的 `ucrt64/bin` 目录加入当前终端的 `PATH`。

修改界面后，关闭模拟器窗口，再执行编译和启动命令。更换编译器时应使用新的构建目录，避免沿用旧工具链缓存。

模拟器和开发板直接编译同一份 `GUI/App/ui.c` 与字体文件，因此界面改动会作用于两端。模拟器使用 Windows 显示驱动和系统内存分配；开发板使用 LCD、触摸适配及 `lv_conf.h` 中的内存配置。模拟器不包含 CAN 接收和 SD 日志硬件逻辑。

模拟器从工作目录下的 `simulator/logs/` 读取历史 CSV。可以将 SD 卡上的 `CANLOG_001.CSV` 等归档文件复制到该目录，也可以在启动时指定目录：

```powershell
.\simulator\build\cansight_sim.exe 'D:\CANLogs'
```

本机目录默认没有日志，不自动生成示例文件。复制的日志不纳入 Git。固件和模拟器共用目录分页、文件名校验及 CSV 解析逻辑，仅底层文件访问分别使用 FatFs 和 Windows C 运行库。

## 界面操作

- 点击“接收”或“SD 回放”切换页面。
- 点击 ID 输入框，使用十六进制键盘输入筛选值。
- 输入 `237` 或 `0x237` 均表示十六进制 ID `0x237`，按数值精确匹配。
- 输入框留空或点击“清除”时取消 ID 筛选。
- 同一 ID 的标准帧和扩展帧均可匹配，表格使用“类型”列区分。
- 接收页筛选只改变显示结果，不影响统计和日志。历史文件筛选将在第 4 阶段接入。
- 接收页每页最多显示 8 条汇总记录，通过 `<`、`>` 翻页，按首次收到该报文组合的顺序排列。
- 类型列中的 `RTR` 表示远程帧；远程帧的数据列为空。只收到一帧时周期为 `--`，之后显示最近两帧的时间间隔，单位为毫秒，保留三位小数。
- 进入“SD 回放”页只刷新历史文件列表，不触发归档。`Refresh` 可手动重新扫描目录。
- 左侧按归档编号从新到旧显示文件，每页 4 项，通过 `<`、`>` 翻页。正在写入的 `CANLOG.CSV` 不在列表中。
- 点击文件名后高亮选中，右侧显示文件大小和开头最多五帧；切换文件前关闭上一个读取句柄，完成预览后也关闭文件。
- `Archive log` 手动归档当前日志。手动或自动归档成功后，正在显示的文件列表自动刷新至首页。
- 文件读取状态与归档状态分别显示；读取失败不修改活动日志的写入状态。
- 模拟器归档区域显示本机预览说明，不执行日志归档。
- 回放页显示 `SD free: 剩余容量 / 总容量 MiB`；进入页面、点击 `Refresh`、归档或删除后更新。数值为查询时快照，不随每帧写入实时变化。
- 选中文件后点击 `Delete file`，确认弹窗显示固定文件名；点击 `Cancel` 不提交删除，点击 `Delete` 后由主循环关闭读取句柄并删除该历史文件。
- 删除成功后清除该文件的预览、重新扫描首页并更新容量；失败时显示数字和 FRESULT 名称。活动日志、目录及任意路径不能作为删除目标，不自动删除旧日志。
- 模拟器显示 `Disk free`，容量来自日志目录所在磁盘；删除操作会实际删除本机目录中选中的历史 CSV。

历史报文的上一帧、下一帧、ID 筛选、播放、暂停和进度控制仍待实现，本阶段不显示未接入的控制按钮。

## CAN 接收与日志记录

当前固件的数据流：

```text
CAN1 FIFO0 中断
    → 读取报文并记录 TIM2 时间戳
    → 放入软件接收队列
    → 主循环取出报文
    → CanLogger_AddFrame() 缓冲 / 写入 CSV
    → CanStats_AddFrame() 更新汇总

LVGL 100 ms 定时器 → 读取统计结果 → 刷新接收表格与总帧数

主循环另行调用 lv_timer_handler() 和 CanLogger_Process()
```

CAN 中断不调用 LVGL 或文件系统。界面由 `ui_init()` 创建，主循环持续调用 `lv_timer_handler()` 处理刷新和输入。

统计模块使用固定的 128 条汇总记录，以 ID、IDE、RTR 共同作为键。同一数值 ID 的标准/扩展帧、数据/远程帧分别统计。表满后，已有记录继续更新，新组合不入表并累计未入表帧数，界面显示 `ID table full` 提示。统计表容量不会限制日志写入，也不会因筛选而改变。

顶部总帧数为主循环交给统计模块的报文数量，包含未入表帧；它等于各条目计数之和加未入表帧数，不包含硬件 FIFO 或软件接收队列中丢失的报文。计数器为 32 位无符号数。周期使用无符号时间戳相减，可跨一次 TIM2 回绕，但同一组合相邻两帧的间隔必须小于约 71.6 分钟。

主循环每轮最多处理 32 帧，再返回 LVGL 处理。逐帧串口打印默认关闭；需要时可将 `CAN_RX_DEBUG_PRINT` 定义为 `1`。

### 运行状态与异常提示

状态栏和异常提示约每 100 ms 更新一次，不以是否收到新报文作为刷新条件。

| 显示 | 判定规则 |
| --- | --- |
| CAN1 未启动 | 控制器未处于监听状态，且未检测到启动失败或当前控制器错误 |
| CAN1 运行中 | HAL 状态为监听，且当前无错误警告、错误被动或 Bus-off 标志 |
| CAN1 错误 | 初始化或启动失败、HAL 错误状态，或当前存在上述控制器错误标志 |
| SD 未挂载 | 尚未成功挂载文件系统，包括启动时无卡或挂载失败 |
| SD 就绪 | 文件系统已挂载，但活动日志尚未就绪；当前主要为初始化中的过渡状态 |
| SD 记录中 | 活动日志已成功打开并完成初始同步，可以接受记录 |
| SD 错误 | 日志打开、格式化、写入或同步失败，日志功能已停止 |

“CAN1 运行中”表示控制器处于接收工作状态，不表示总线上一定有其他设备。停止报文发送不会改变该状态。错误警告或错误被动状态解除后可重新显示运行中；当前未实现 Bus-off 自动恢复及启动失败后的自动重试。

异常栏各字段定义如下：

- `Queue lost`：软件接收队列已确认丢弃的帧数。
- `FIFO overruns`：硬件 FIFO0 溢出事件数，无法据此推算精确丢帧数。
- `HAL`：本次启动以来累计发生的 HAL CAN 错误位，以十六进制显示。
- `SD`：最近一次日志相关错误，显示数字和 FRESULT 名称，例如 `SD: 3 (FR_NOT_READY)`；成功初始化时为 `0 (FR_OK)`。

上述异常记录持续保留至设备复位，历史错误与当前 CAN 状态分别显示。SD 状态来自文件系统操作结果，不提供独立的物理插卡检测；拔卡后的状态更新取决于后续文件操作何时返回错误。本阶段不支持热插拔后的自动重新挂载。

### 日志归档规则

活动日志保存在 SD 卡根目录的 `CANLOG.CSV`，历史日志使用 `CANLOG_001.CSV` 等名称。

1. 启动时扫描现有历史文件编号，将旧的非空活动日志归档，再创建本次启动的活动日志。
2. 点击 `Archive log` 后，界面仅提交请求。主循环在写出缓冲、同步并关闭活动文件后执行重命名，成功后创建新活动日志继续记录。页面切换不归档。
3. 编号从现有最大编号递增，至少三位，超过 999 后自然扩展位数；最多支持九位编号。重命名前检查目标是否存在，不覆盖旧文件或同名目录。
4. 零字节文件及内容完全等于 CSV 表头的文件不生成历史文件。其他旧文件即使格式未知，也保留并归档，不按文件大小简单丢弃。
5. 当前日志没有接收记录时，归档请求返回 `No frames; archive skipped`，继续使用原活动文件。
6. 归档任一步失败即停止日志并显示错误，不截断已有数据。若归档成功但新活动文件创建失败，历史文件仍保留，归档状态显示失败以提示记录尚未恢复。
7. 活动文件达到约 10 MiB 时自动归档。大小计算包含 CSV 表头和 RAM 中待写出的记录，按完整报文边界切分，单个新生成文件不超过该上限；已有历史文件不重新切分。阈值由 `CAN_LOG_MAX_FILE_SIZE` 配置。

归档请求与接收出队处理均在主循环中顺序执行；实际切换文件之前处理的报文仍属于旧文件，之后处理的报文进入新文件。归档操作期间 CAN 中断仍接收并入队，但同步文件操作可能暂时阻塞主循环，不能据此保证高负载下零丢帧，应关注接收异常计数。

日志继续使用 4096 字节文本缓冲区，主循环约每秒写出剩余记录并调用 `f_sync()`。V0.4 支持手动删除历史日志，尚未实现 SD 热插拔恢复。

### 存储容量与历史文件删除（V0.4）

容量查询使用 `f_getfree()` 返回的空闲簇数和卷参数，按实际扇区大小换算，并在乘法前扩展为 64 位，避免大容量卡发生 32 位溢出。总容量表示文件系统的数据区容量，不是卡的标称容量；`1 MiB = 1,048,576` 字节。剩余空间包含整卷其他文件的占用影响，不包含尚未写入的 RAM 日志缓冲。

剩余空间小于 10 MiB 时显示黄色 `LOW SPACE` 提示。提示基于最近查询结果，不代表剩余可记录时长，也不保证还能写完一个完整日志。空间耗尽后的短写由日志模块报告为 `FR_DISK_ERR`，日志停止写入；删除文件不会自动恢复已停止的日志功能，需处理故障后复位。

删除请求锁定确认时的规范归档文件名，执行前关闭历史读取及目录句柄，并检查目标不是目录。固件使用 `f_unlink()`，模拟器使用 Windows 文件接口；模拟器还拒绝重解析点。活动 `CANLOG.CSV` 不符合归档名称校验，不能通过此接口删除。删除不重编号已有文件，日志模块继续使用当前分配的后续编号。

容量查询、删除、预览和活动日志写入均由同一主循环顺序执行，不在 LVGL 回调或 CAN 中断内访问文件系统。容量与删除错误独立显示，不覆盖活动日志模块的状态。容量查询和删除是同步操作：FatFs 首次查询可能需要遍历 FAT 表，删除需要释放文件簇链，较大卷或较大文件可能造成明显等待。CAN 中断在此期间仍可入队，但当前不能保证高负载下不发生队列溢出；相关性能优化保留至 V0.7。

本阶段不引入 RTC 或日期时间，继续保留 TIM2 报文时间戳用于周期计算及后续回放。

常见 SD 错误如下，完整枚举以项目自带的 FatFs `ff.h` 为准：

| 错误码 | 名称 | 含义 |
| --- | --- | --- |
| 0 | FR_OK | 操作成功 |
| 1 | FR_DISK_ERR | 底层磁盘读写错误；短写也统一报告为此错误 |
| 3 | FR_NOT_READY | 存储设备未就绪 |
| 7 | FR_DENIED | 操作被拒绝、目录已满等；本模块编号耗尽也报告此错误 |
| 13 | FR_NO_FILESYSTEM | 未识别到有效 FAT 文件系统 |
| 16 | FR_LOCKED | 文件共享策略禁止当前操作 |

CSV 格式示例：

```csv
timestamp_us,format,type,id,dlc,data_hex
123456,STD,DATA,0x237,8,12 27 65 74 83 92 87 33
123956,EXT,REMOTE,0x123,8,
```

| 字段 | 含义 |
| --- | --- |
| `timestamp_us` | 接收时的 TIM2 计数值，单位为微秒，不是日期时间 |
| `format` | `STD` 为标准帧，`EXT` 为扩展帧 |
| `type` | `DATA` 为数据帧，`REMOTE` 为远程帧 |
| `id` | 十六进制 CAN ID |
| `dlc` | DLC，当前接收路径限制为 0～8 |
| `data_hex` | 以空格分隔的十六进制数据字节；远程帧为空 |

当前时间戳约每 71.6 分钟回绕一次，设备复位后重新计时。新采集日志不再跨启动追加，但长时间日志及旧版本遗留日志仍可能包含时间回绕或复位分界；后续回放阶段需要处理这些边界。本阶段未更改 CSV 字段或引入 64 位时间戳。

### 历史文件读取

`LogPlayer_Process()` 在主循环中位于日志处理之后。单轮最多扫描 4 个目录项或读取 256 字节；不一次性读取整个目录或整份日志。分页扫描只保留当前页所需的 4 个候选条目，内存占用不随历史文件数增长。为保持编号排序，每次翻页会分批重新扫描目录，目录较大时显示 `Scanning...`。

文件名必须符合项目生成的 `CANLOG_001.CSV` 至九位编号格式，字母不区分大小写，不接受活动文件、目录或任意路径。预览使用只读模式；只有确认删除后才移除目标历史日志。固件 FatFs `_FS_LOCK` 已设为 4，并同步到 `.ioc`，用于容纳活动文件、历史读取和目录扫描。

CSV 首行必须匹配当前日志表头，允许 UTF-8 BOM、LF 或 CRLF 行结束符。每条报文校验十进制 32 位时间戳、STD/EXT、DATA/REMOTE、ID 范围、DLC 0～8 及实际数据长度；远程帧数据列必须为空。行缓冲固定为 128 字节，超长行或异常内容会停止预览并报告行号，保留此前有效帧，不将错误内容作为报文显示。

界面区分无历史文件、目录扫描失败、文件打开/读取失败、空日志和 CSV 格式错误。读取与活动日志状态分别维护；已读到五帧即结束预览，不继续检查后续内容，因此 `Preview ready` 不表示整份文件均已验证。时间列显示原始微秒时间戳转换后的秒数，暂未展开回绕。

如果底层资源关闭失败，读取模块暂停后续文件访问，避免覆盖未释放的文件对象；需要复位后重新初始化。本阶段未提供 SD 热插拔或故障后的自动恢复。

## 字体与内存

界面使用 `lv_font_cansight_14`，由 `NotoSansSC-Regular.ttf` 转换为 LVGL C 字体，字号 14 px、4 bpp，未启用压缩。字体仅包含 ASCII 和当前界面所需的中文、符号，不包含完整中文字库。

新增中文文案时，需要将新增字符加入字体转换范围并重新生成 `GUI/App/lv_font_cansight_14.c`。转换参数记录在该文件头部。字体源码已加入根目录和模拟器的两份 `CMakeLists.txt`；替换文件且保留名称时无需再次添加。

STM32 当前配置了 32 KB LVGL 内存池，另有 800 × 10 像素的 RGB565 显示缓冲区，占 16000 字节。链接报告中的 SRAM 占用包含预留的 LVGL 内存池，但不能反映池内运行时剩余空间。增加控件和业务缓冲区时，应同时关注链接占用、运行时分配和栈空间。

主栈预留为 4 KB，链接脚本和 CubeMX `.ioc` 已同步配置。归档函数与 FatFs 长文件名处理存在嵌套调用，编译器栈报告表明原先的 1 KB 预留不足；4 KB 是当前预留值，后续仍需结合中断嵌套和实机运行检查余量。

## 开发说明

- CubeMX 生成文件中的自定义代码应放在 `USER CODE` 区域，重新生成后检查差异。
- `Core/Src/can.c` 的 `HAL_CAN_Init()` 失败分支已改为返回，由主循环显示错误。该分支位于生成区域，CubeMX 重新生成后须核对，避免恢复为阻塞式 `Error_Handler()`。
- 新增共用界面源码时，分别更新固件和模拟器的 CMake 配置。
- 逐帧串口调试输出使用阻塞发送，默认关闭；开启后会影响高报文速率下的处理能力。
- `build/` 等构建目录与 `.vscode/` 本地配置不纳入版本管理。若本地关闭 cSpell，提交前应自行检查命名和拼写。
- STM32 HAL、CMSIS、FatFs、LVGL 和字体等第三方内容遵循各自附带的许可说明。
